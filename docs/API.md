# Viri Blockchain API Documentation

## Overview

The Viri blockchain provides multiple API interfaces for interacting with the network:

- **JSON-RPC 2.0 API** - Available on port `8545` for Ethereum-compatible RPC calls
- **REST API** - Available on port `8546` for RESTful operations
- **WebSocket API** - Available on port `8547` for real-time subscriptions

Base URLs:
- RPC: `http://localhost:8545`
- REST: `http://localhost:8546`
- WebSocket: `ws://localhost:8547`

## Authentication

The Viri blockchain API supports API key authentication through multiple methods:

### API Key via Header
```
X-API-Key: your-api-key-here
```

### Bearer Token
```
Authorization: Bearer your-api-key-here
```

### Query Parameter
```
GET /api/v1/status?api_key=your-api-key-here
```

### Generating API Keys
API keys can be generated by administrators using the node CLI:
```bash
viri-cli api-key create --description "My API key"
```

### API Key Permissions
API keys can have the following permission levels:
- `read` - Read-only access to all endpoints
- `write` - Read and write access (can send transactions)
- `admin` - Full administrative access

## Rate Limiting

Rate limiting is applied per API key (or IP address if no API key is provided).

| Tier | Requests per Second | Burst Limit |
|------|---------------------|-------------|
| Unauthenticated | 10 | 20 |
| Read | 50 | 100 |
| Write | 30 | 60 |
| Admin | 100 | 200 |

Rate limit headers are included in all responses:

```
X-RateLimit-Limit: 50
X-RateLimit-Remaining: 49
X-RateLimit-Reset: 1625097600
```

When rate limit is exceeded, the API returns:
- **HTTP Status**: `429 Too Many Requests`
- **JSON-RPC Error Code**: `-32000`

## TLS Setup

To enable TLS for secure connections:

### Configuration
Add the following to your node configuration file:

```yaml
api:
  tls:
    enabled: true
    cert_file: /path/to/cert.pem
    key_file: /path/to/key.pem
```

### Using Self-Signed Certificates (Development)
```bash
openssl req -x509 -newkey rsa:4096 -keyout key.pem -out cert.pem \
  -days 365 -nodes -subj "/CN=localhost"
```

### Production TLS
For production, use certificates from a trusted CA such as Let's Encrypt:

```bash
certbot certonly --standalone -d your-domain.com
```

TLS-enabled base URLs:
- RPC: `https://localhost:8545`
- REST: `https://localhost:8546`
- WebSocket: `wss://localhost:8547`

## JSON-RPC 2.0 API

The JSON-RPC API follows the [JSON-RPC 2.0 specification](https://www.jsonrpc.org/specification).

**Endpoint**: `POST http://localhost:8545`

**Content-Type**: `application/json`

### Request Format
```json
{
  "jsonrpc": "2.0",
  "method": "eth_blockNumber",
  "params": [],
  "id": 1
}
```

### Response Format
```json
{
  "jsonrpc": "2.0",
  "result": "0x1b4",
  "id": 1
}
```

## WebSocket API

**Endpoint**: `ws://localhost:8547` (or `wss://localhost:8547` with TLS)

The WebSocket API allows real-time subscriptions to blockchain events.

### Connection

```javascript
const ws = new WebSocket('ws://localhost:8547');

ws.onopen = () => {
  console.log('Connected to Viri WebSocket API');
};

ws.onmessage = (event) => {
  const data = JSON.parse(event.data);
  console.log('Received:', data);
};

ws.onerror = (error) => {
  console.error('WebSocket error:', error);
};

ws.onclose = () => {
  console.log('Disconnected from Viri WebSocket API');
};
```

WebSocket connections support authentication via query parameter:

```
ws://localhost:8547?api_key=your-api-key-here
```

```json
{
  "type": "auth",
```

## Error Handling

### JSON-RPC Error Format

JSON-RPC errors follow the standard format:

```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32600,
    "message": "Invalid Request",
    "data": {
      "details": "Missing required parameter: params"
    }
  },
  "id": 1
}
```

### Standard JSON-RPC Error Codes

| Code | Message | Description |
|------|---------|-------------|
| `-32700` | Parse error | Invalid JSON was received |
| `-32600` | Invalid Request | The JSON sent is not a valid Request object |
| `-32601` | Method not found | The method does not exist / is not available |
| `-32602` | Invalid params | Invalid method parameters |
| `-32603` | Internal error | Internal JSON-RPC error |

### Custom Error Codes

| Code | Message | Description |
|------|---------|-------------|
| `-32000` | Server error | Generic server error |
| `-32001` | Transaction rejected | Transaction was rejected |
| `-32002` | Insufficient funds | Account has insufficient funds |
| `-32003` | Nonce too low | Transaction nonce is too low |
| `-32004` | Gas limit exceeded | Transaction exceeds gas limit |
| `-32005` | Block not found | Requested block does not exist |
| `-32006` | Transaction not found | Requested transaction does not exist |
| `-32007` | Rate limit exceeded | Too many requests |

### HTTP Error Codes (REST API)

| Code | Message | Description |
|------|---------|-------------|
| `400` | Bad Request | Invalid request parameters |
| `401` | Unauthorized | Invalid or missing API key |
| `403` | Forbidden | Insufficient permissions |
| `404` | Not Found | Resource not found |
| `429` | Too Many Requests | Rate limit exceeded |
| `500` | Internal Server Error | Server error |
| `503` | Service Unavailable | Service temporarily unavailable |
